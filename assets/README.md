# 本地媒体

当前发布资源以 `release-media.json` 为准。`scripts/build.py` 校验每项来源与 SHA-256 后打包，应用离线播放，不依赖开发时的渲染工具。

- `artwork/guijing-icon.svg`：归径的圆角图标母图，构建时转成 ICNS。`artwork/v1/icon/` 保留旧图标与历史派生文件。
- `artwork/v3/`：六场景背景及透明图层，供 `scripts/nature_entry.py` 重建五秒入场视频。
- `media/v3/`：当前场景背景、无声入场视频及制作／验证资料。`*-work.wav` 和有声 `*-preview.mp4` 是旧音轨制作资料，仍被入场管线和 `app:media` 校验使用，不能当作当前发布音乐，也不能直接删除。
- `media/v4/`：六套完整曲目组、曲序、来源、权利声明及制作报告。正式采用的六个文件由发布清单指定。`forest-program-mix.m4a` 供先前森林整曲组校验使用，与当前森林曲目字节相同，保留其旧入口。
- `media/guide.aiff`：本机 Tingting 预制引导语音。

2026-11-06 再次核对当前 v4 制作报告后，清理了五个被替代且只在旧清理记录中出现的哈希输出。此前已清理旧 v1 角色／场景 PNG 及重复 ZIP、根目录旧合成 WAV和 v2 音频／视频。v1／v2 提示词、清单与制作说明保留为历史快照，里面的路径不代表文件仍在当前工作树。`scripts/scene_animation.py` 的旧输入已移除；如需复现旧版，应先从清理前的提交恢复对应素材。当前构建与六场景媒体校验不依赖这些旧输入。

旧资源的忽略规则防止旧制作脚本输出被再次误提交。重新制作 v4 音乐后，只提交发布清单／制作报告采用的版本，不保留同场景的废弃哈希文件。

文件删除不会移除 Git 历史对象。已进入提交的大文件仍可能使 push 失败；需要单独审阅并确认历史清理范围。当前音乐来源见 `../docs/声音素材来源.md`，实际听感及连续两轮播放的未验收项仍沿用原记录。
