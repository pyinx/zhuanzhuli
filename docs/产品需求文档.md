## 1. 文档约定

本文记录已经确认的产品意图、首版范围和行为要求。原始需求保留作为背景；存在差异时，以本轮最后确认的决策为准。后续调整应明确记录原因和影响，并由用户确认，不以技术实现便利为由静默修改需求。

“已确认”表示产品决策已经确认，不表示功能已经实现。“待验证”表示尚未取得实现、兼容性或真实用户效果的证据。竞品能力也不能直接证明本产品具备同等能力。

本文件不确定具体界面像素、底层 API、数据表结构或工程架构。最低系统版本、硬件支持范围、性能数值和尚未明确的交互细节，在验证后形成提案，不在本文中补作已确认决定。

## 2. 问题与定位

### 2.1 要解决的问题

AI 办公中，用户可能在等待回复、处理临时念头和切换工具时，从原本的任务 A 转向 B、C，逐渐失去当前目标。工作结束后感觉疲惫、忙于应付，却缺少推进事情的成就感。

这是来自原始需求和本次访谈的问题陈述，尚不代表已经通过独立用户研究证实了市场普遍性。

多个窗口不必然等于分心。查资料、向 AI 提问和编写文档可能共同服务于一个目标。产品首先减少非必要的任务偏离，同时保留推进目标所需的工具协作。

### 2.2 首批用户

用户本人，以及与其类似、日常并行使用多个 AI 工具的桌面办公者。学习等场景是后续扩展方向，不作为首轮验证的主要人群。

### 2.3 核心价值

用户选定一件事后，可以轻松进入一个安静、有边界的工作环境；工作时工具顺手，结束后平稳回到日常状态。

首版优先验证当下能否减少任务偏离、帮助持续推进目标。平静和沉浸感服务于这个目标。长期专注力训练、离开产品后的注意力改善，暂不作为已经证实的产品效果。

## 3. 首版范围

| 类别 | 首版要求 |
| --- | --- |
| 平台 | 首先验证 macOS 完整体验，保留后续跨平台可能性 |
| 工作单位 | 一句当前目标，可由多个相关应用共同完成 |
| 时间 | 15、30、60 分钟预设及自定义；到点提醒一次，自动继续计时 |
| 应用管理 | 选择允许应用，保存与复用组合，收起其他应用，温和处理范围外访问 |
| 通知 | 通过系统专注模式保护可控制的标准通知弹窗和提示音；关键警报、部分系统／来电及自绘提醒为已确认例外 |
| 沉浸体验 | 森林、沙滩、雪地、草原；本地小人入场短片、安静的临时背景、可选声音与人声引导 |
| 会话控制 | 开始、暂停、恢复、退出专注；没有休息功能 |
| 记录 | 静默自动保存，可主动查看和删除历史 |
| 数据 | 核心功能本地可用，无需登录，不读取工作内容，不依赖外部 AI 接口 |
| 初始交付 | 小范围免费验证，不加入支付、订阅或授权机制 |

以下功能不纳入首版：通知白名单、网站或标签页限制、应用内容识别、任务清单管理、休息倒计时、番茄钟循环、强制复盘、积分与连续打卡、云同步、实时可操控 3D 世界、智能灯光联动。

通知白名单已明确列为二期方向。跨平台和 App Store 上架属于后续目标，不承诺在首个验证版本同时交付。其他排除项不自动转为后续开发计划。

## 4. 主流程与界面职责

### 4.1 主流程

明确或复用目标 → 选择时长 → 点击开始 → 建立专注环境并播放可跳过的入场短片与可选引导 → 使用原生应用工作 → 到点后继续计时，或随时暂停、恢复、退出。

保护建立失败时进入明确的配置或选择流程，不能假装已经生效。结束后静默保存记录，不弹总结。

### 4.2 界面职责

| 界面 | 主要职责 | 信息与操作 |
| --- | --- | --- |
| 开始面板 | 以很低的准备成本进入专注 | 一句目标、时长、开始按钮；应用组合、场景和声音可展开修改 |
| 入场过渡 | 帮助用户切换到专注状态 | 本地小人进入场景的短片，可跳过；人声引导可选 |
| 工作环境与轻量控制入口 | 支持实际工作，随时可控 | 原生应用窗口、安静背景；可查看目标、计时、保护状态，执行暂停、恢复或退出 |
| 历史清单 | 用户主动回看投入 | 日期、目标、实际计时时长、会话状态、删除操作 |
| 设置与首次配置 | 配置可复用的环境与必要系统权限 | 应用选择、场景、声音、引导、必要系统配置与生效状态 |

轻量控制入口可参考菜单栏面板，具体形态在交互设计中验证。首版不要求持续占据工作区域的大面板，也不因用户查看计时而将工作应用移出前台。

## 5. 功能要求

### R01 当前目标

- 每次专注明确一句当前要推进的事情，例如“完成方案第一版”。
- 允许复用之前的目标，不要求创建项目、拆解子任务或维护待办列表。
- 一个目标可以使用多个应用，不能把切换相关应用直接判断为分心。
- 本产品不读取文档或聊天来判断目标完成情况。

### R02 时长选择

- 提供 15、30、60 分钟按钮及自定义时长。
- 不强制固定的工作与休息节奏。
- 用户可提前退出，已投入的有效计时时间仍然保存。
- 首次默认选中项、自定义范围与单位、入场过渡是否计入时长尚未明确，见待验证清单 V06；不得将任意实现值标为已确认需求。

### R03 应用选择与组合复用

- 用户选择本次允许使用的应用，并能保存、复用应用组合。
- 日常开始时沿用已保存的选择，可以展开调整，不要求每次重新配置。
- 管理粒度为应用，不对网站、标签页、聊天对象或文档内容进行限制和分类。
- 应用使用许可与通知许可分开：允许工作的应用，其标准通知也属于 R06 保护范围。

### R04 应用收起与范围外访问

- 进入专注时收起未选择的应用，保留后台运行；不关闭应用或终止其任务。
- 用户主动打开未选择应用时，提供“返回当前工作”“加入本次专注”“退出专注”三个选择。
- “加入本次专注”只明确改变本次允许范围，不自动改写已保存组合。
- 用户始终拥有退出权，不锁住电脑，不惩罚退出，不持续争抢输入焦点。
- 正常拖拽、文件选择器、输入法与必要系统交互不能被误当作分心操作拦住；具体系统边界需验证。

### R05 原生应用与多屏工作

- 用户继续操作原来的浏览器、AI 工具、编辑器和文档窗口。
- 多个允许应用保持正常亮度，可以并排使用。
- 不强制放大为单个窗口，不自动搬动或重新排列已有工作窗口。
- 所有显示器共享同一目标、计时与应用范围；相关应用可以分布在不同屏幕。
- 各屏提供同主题背景，不要求拼接为一幅全景。
- 多桌面、全屏应用、窗口管理功能等兼容性尚需验证，不能从多屏需求直接推断已经支持所有系统组合。

### R06 通知屏蔽

- 2026-10-23 用户明确选择“接受明确边界，继续实现与验证联动”：首版改为保护系统专注模式可控制的标准通知弹窗和提示音，不提供应用或联系人白名单。
- 关键警报、部分 macOS 系统提醒／来电和应用自绘提醒属于明确例外，不承诺全渠道屏蔽。时效性通知、允许联系人、重复来电和智能突破等系统配置须在首次设置时说明与核对。
- “不处理应用内部内容”继续指不分析或限制网页、聊天、文档等工作内容；不通过读取内容控制自绘提醒。
- 标准应用通知和可被 Focus 控制的系统通知仍需分别取得开启前正向基线、开启后的弹窗／声音及恢复证据。范围确认不代表联动已经实现或验收通过。
- 不采用系统总静音替代通知屏蔽；本产品的音乐、引导及用户主动播放的工作内容需要与通知声音区别处理。
- 允许一次性必要系统配置；不引入快捷指令，不要求用户安装第三方工具或外部脚本运行环境。
- 二期再考虑通知白名单。不得将二期白名单能力写成首版已提供功能。
- 可达范围若与目标不一致，形成证据与调整方案，由用户确认后更新要求。

### R07 保护状态与失败处理

- 系统配置完成、权限已授予、接口调用成功和实际屏蔽生效是不同状态，不能混用。
- 只将已验证生效的能力展示为已生效；无法验证时如实显示未验证或受限状态。
- 保护不完整时，默认引导解决问题，并允许完成配置、明确选择以部分保护继续，或取消进入。
- 用户未明确选择前，不静默进入部分保护，也不显示“全部通知已屏蔽”等无证据承诺。
- 进入部分保护后保留相应状态说明，不通过反复弹窗打断用户。

### R08 场景与入场短片

- 首版包含森林、沙滩、雪地、草原四个主题。
- 通过本地播放的小人入场短片呈现进入隔离空间的立体感，参考长度约 5–10 秒。
- 随时可跳过，重复使用时可以直接进入；不提供角色操控、自由走动或镜头探索。
- 四个主题保持统一的角色、画面、声音和过渡语言。
- 具体美术风格、分镜、媒体参数及素材来源尚待设计与资源验证。

### R09 工作背景

- 入场结束后以静态或近乎静止的场景衬托实际工作，默认低干扰。
- 主要视觉空间让给工作应用，不持续播放明显角色动作或运动镜头。
- 优先评估本次专注期间临时呈现的背景，退出后撤去；尽量减少修改系统桌面设置。
- 具体窗口层级、背景呈现方式、全屏兼容及退出恢复能力必须验证，不在需求中指定未经验证的底层实现。
- 不可见的动态画面应停止无效渲染，相关性能证据见 V14。

### R10 音乐与人声引导

- 支持轻柔音乐或环境声音，音量独立控制。
- 视觉、人声引导和背景声音可分别控制，并记住用户偏好。
- 人声引导默认关闭，用户主动选择开启，主要在进入阶段出现且可跳过。
- 工作中不突然插入人声；不默认增加阶段性催促或周期提醒。
- 场景、音乐与引导具备本地可用基础资源，核心体验无需外部服务。
- 声音衔接、循环接缝、设备切换及通知静音共存情况需验证。

### R11 计时与到点继续

- 计时依据会话实际经过时间，扣除暂停时间；不依赖界面是否打开。
- 到点只提醒一次，使用不抢焦点的轻提示，可选一次短促柔和的声音，用户可以关闭提醒声音。
- 该到点提醒是用户主动选择的会话反馈，应与被屏蔽的外部通知分开处理，并验证两者共存。
- 到点后自动进入超时计时，展示已超过预设时长，继续累计实际投入，无需点续时才能继续。
- 不自动切换界面、撤销保护、结束会话或重复催促。

### R12 暂停与恢复

- 用户可以随时暂停。暂停期间立即停止计时与环境声音，解除可确认归属的应用限制。通知改动无法证明连续归属时，按 R14 由用户确认收尾，不猜测关闭系统模式。
- 恢复后继续原目标与计时阶段，并重新启用本次专注保护。
- 有待核对通知记录时先处理；保留已有同名模式后可借用，恢复仍须明确接受当前保护边界。一键开始流程保持不变。
- 倒计时阶段暂停，恢复后继续剩余时间；超时阶段暂停，恢复后继续累计超时时间。
- 暂停期间不自动开启下一段，也不将暂停转换为休息功能。

### R13 自动暂停与闲置边界

- 锁屏、合盖或系统睡眠时自动暂停；回来后保留会话，由用户主动恢复。
- 不把休眠或锁屏期间的时间累计为专注时间。
- 不因一段时间没有键鼠操作而自动暂停，不通过操作频率判断分心。
- 阅读、思考、等待 AI 等没有操作的阶段可以属于正常工作。

### R14 退出与环境恢复

- “退出专注”结束本次会话；区别于暂时离开的“暂停”，也区别于退出应用程序。
- 退出专注后停止相应计时和声音，撤去背景与应用限制，恢复本产品改变的环境状态。
- 恢复时保留原本就隐藏的应用及原有系统状态，不能简单执行“显示全部应用、关闭所有专注模式”。
- 2026-10-24 用户明确接受确认式通知收尾：无法证明连续归属时，用户暂停、结束或正常退出应用提供“保留当前模式／关闭此模式／稍后核对”，默认保留。只处理本次记录的指定模式。
- 保留当前模式不切换系统，仅在原子保存成功后释放本地记录；明确关闭先重新核对指定模式及其他开启模式，状态改变则停止，实际观察指定模式关闭及面板清理完成后再释放记录。失败保留记录、就地说明并允许重试，不以请求发出当作关闭成功。
- 稍后核对、Esc 或关闭选择窗保留系统状态与记录；会话保持暂停或结束，新开始／恢复受阻。正常退出应用需先完成核对及其他清理；稍后核对则留在应用，不掩盖其他恢复错误。
- 锁屏、睡眠等非用户触发暂停和异常重开不自动弹出收尾选择，不自动关闭未知归属模式；回到应用后由用户主动处理。确认式收尾不等于已验证通知抑制效果，也不覆盖“本轮不切换系统 Focus”的测试边界。
- 正常关闭应用以及异常退出后的清理和恢复策略需验证；不能留下无法解除的遮罩或应用限制。
- 崩溃、强退或断电不应将未知时间补算为有效专注，更不能自动认定目标已完成。

### R15 静默记录与历史

- 自动保存目标、日期、预设时长、实际有效计时时长和会话状态等必要记录。
- 记录不依赖用户填写感受、评价进度或完成复盘。
- 会话状态描述开始、暂停、结束或异常中断等事实，不表示任务是否成功完成。
- 结束后不弹总结，不主动推送回顾。
- 用户可以主动打开简单历史清单查看记录，并支持删除。
- 不增加统计大屏、排行榜、积分或连续打卡机制。

### R16 本地与隐私

- 核心功能本地可用，无需账号，不依赖云服务或外部 AI 接口。
- 目标、组合、偏好和会话记录保存在本机。
- 不读取工作文档、聊天内容或屏幕内容来判断专注，不将时长宣传为检测得到的注意力水平。
- 不为首版引入内容识别、云端分析、跨设备同步等额外能力。
- 实际网络依赖、权限与数据删除行为必须检查，不能仅凭设计声明认定满足要求。

## 6. 会话状态约定

| 状态 | 计时 | 应用与通知保护 | 声音与背景 | 用户可执行 |
| --- | --- | --- | --- | --- |
| 准备 | 未开始 | 未建立 | 不影响原工作环境 | 修改配置、开始 |
| 进入 | 建立保护并播放过渡；计时边界待定 | 检查和建立；失败则明确告知 | 可跳过短片和可选引导 | 跳过过渡、取消进入 |
| 专注中 | 倒计时并累计有效时长 | 维持已生效保护，受限状态如实显示 | 低干扰背景与可选声音 | 暂停、退出、处理范围外应用 |
| 超时专注 | 正向累计超时和有效时长 | 保持 | 保持，轻提示只发生一次 | 暂停、退出 |
| 暂停 | 停止累计 | 解除可确认的应用改动；通知按 R14 核对 | 停止声音，撤去对应保护效果 | 恢复、退出 |
| 已退出 | 停止并保存 | 清理本产品改动 | 停止并撤去 | 主动开始下一次、查看历史 |

锁屏、合盖和睡眠从专注中或超时专注进入暂停；唤醒不自动恢复。恢复回到暂停前的计时阶段。异常中断的事实记录与恢复流程见 V05、V07、V15。

## 7. 体验与验收原则

1. 日常进入成本低：目标、时长和开始操作突出，已有应用组合、场景与声音可直接复用。
2. 工作为主：允许应用顺手协作，不抢焦点、不自动重排窗口，不让界面持续争夺注意力。
3. 自主可控：暂停与退出始终可达；范围外应用访问提供明确选择，不惩罚用户。
4. 恢复可信：退出后的环境恢复与进入体验同等重要；正常退出和异常情况均应验证。
5. 状态诚实：无法验证的保护不显示为已生效；部分保护需用户明确选择。
6. 记录克制：静默保存事实，主动查看，不推断注意力或任务成果。
7. 质量要求：交互简洁、视觉精致，符合 macOS 使用习惯和苹果风格的克制感；具体视觉方案需单独评审。

本轮没有确定启动秒数、CPU、内存、包体或续航等数值，不在此虚构验收指标。测量方法、支持范围和阈值应先形成证据，再补充到验证结论。

用户效果验证应围绕任务偏离是否减少、目标是否更易持续推进、使用成本和信任感展开。喜欢场景、累计时长多或尝试打开范围外应用次数少，均不能单独证明产品已经改善专注。

## 8. 技术、分发与验证顺序

- 主技术栈为 Go＋MyGo，允许打包 macOS 专用适配代码。
- 系统能力必须逐项验证；框架支持通知发送，不等于支持全面通知屏蔽。
- 用户无需额外安装运行环境、第三方插件、脚本工具或快捷指令。使用操作系统内置能力不等于引入第三方组件，但必须满足已确认的无快捷指令约束。
- 先在 macOS 验证完整体验，架构保留后续跨平台空间；不承诺所有系统能力可以直接跨平台复用。
- 如核心体验与 App Store 限制存在实际冲突，允许先提供签名、公证安装包，再评估上架版本范围。
- 首个验证版本供本人和少量相似用户持续试用，不加入支付、订阅、授权系统。
- 下一阶段应先验证关键系统边界，再决定详细设计与资源投入；当前仅形成清单，不执行开发、配置修改、打包或发布。
