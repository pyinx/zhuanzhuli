# 原生界面优化与开发收口

2026-10-24。阶段：继续开发及开发回归；未进入正式整体验收。依据：用户本轮完整开发及 apple-design 指令、需求 v1.2、v0.2 窗口组织与 D13 收尾契约。

## 本轮实际修改

主窗保持目标、时长、场景、边界确认、开始的顺序。使用 AppKit 系统半粗体建立标题和分组层级；时长预设改为真正的 NSSegmentedControl，15／30／60 显示明确选中状态。自定义值与预设实时对应，非预设值清除预设高亮。场景预览按本地图片比例显示并裁切圆角，不增加动态装饰。

设置按应用、声音和通知分组，背景采用 NSBox 与语义 controlBackgroundColor，文字跟随系统 label／secondaryLabel 色。窗口圆角、阴影、交通灯、按钮按压与焦点环交给 macOS。没有复制网页玻璃层，也没有为无手势的桌面控件引入弹簧库。继续使用原生文本输入及既有减少动态效果路径。

通知收尾窗口保持 D13 的三个选择，默认“保留当前模式”放在右侧，“稍后核对”放在左侧；保留 Enter、Esc 语义与失败记录。这个最终布局尚未取得本轮截图或实际按钮取证。

## 键盘检查及修正

本轮最初手动串联 key view 并关闭自动重算。实际 CUA 操作三次显示 Tab 能进入分钟输入，但反向 Shift+Tab 留在原字段；本应用本地事件记录确认收到了 Shift 标志，不能归咎于工具没有发送修饰键。改回 AppKit 自动维护焦点链后，实际 Tab／Shift+Tab 回到目标输入。临时 Tab 日志已移除。隔离状态仅观察本应用的字段编辑状态，不监听其他应用输入。

原生构造检查新增正反向 field-editor 命令回归。260／266 的前向断言失败来自检查直接调用 NSWindow，绕过了原生文本编辑结束；核对真实输入路径后改由 field editor 执行 insertTab／insertBacktab。268 两项实际 AppKit 检查通过。它不是完整键盘、IME 或 VoiceOver 验收；也没有修改系统键盘导航设置。

## 工作应用交接

262 实际复现：从另一个前台夹具返回工作时，旧逻辑先激活隐藏宿主，观察到 hostActivated=true。这一中间阶段也是历史 229 超时所在的等待点。现移除宿主激活等待，采用 SDK 已公开的 yieldActivationToApplication／activateFromApplication；仍核对目标实例，仍实际观察目标获得前台，不以请求返回代替生效。

入场与恢复保留主窗口，目标真正获得前台后才收起主窗。系统明确拒绝后台切换时立即报错，保留当前前台并提供 Dock 路径，不循环争抢焦点。265 实测系统拒绝背景来源，这纠正了“背景请求应总能成功”的测试假设；拒绝与目标实际激活分别记录。该分支只接受明确的系统拒绝，不能以任意错误代替。

271 的 16 项自有夹具检查通过：可用目标实际激活、原本已活动的工作应用不被打断、当前工作优先、后台拒绝不激活宿主、真实 enter 回调保留窗口直到交接、结束并清理等。该次后台拒绝耗时 7 ms，两个清理记录均无未决改动。此结果不能证明所有 Spaces、第三方应用或所有历史偶发失败已经归因。

后续试图回滚入场顺序作对照，273 在前置“可用应用返回”即收到系统拒绝，尚未进入目标断言；恢复当前代码后 275 同样发生。没有将它们记为该断言的先红证据。重新检查前提后，为开发夹具增加等待宿主真实前台就绪；277 超时，随后 CUA 明确报告桌面锁定。本轮不再反复运行需要前台的检查，不要求用户解锁，不绕过锁屏。
