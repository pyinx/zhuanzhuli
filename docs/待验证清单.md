## 1. 使用规则

0.4.0 本地候选新增待验收：六段 8 秒实拍入场的第一人称感与接续；引导人声自然度；音乐和四种录音的完整两轮听感；系统输出正常时真实一分钟到点可听一次；浅深色／最小窗口、原生日历和完整开始／暂停／恢复流程。原生自动验收遇到“窗口可见但未成为前台”前置条件失败，保留失败证据，不据此判定完整 UI 或交接通过。命令记录见本轮 harness change，旧版本通过结果不替代本轮。

索引保留各项计划，已取得的分项证据不等于整项验收。已查阅官方资料只属于研究依据，不算能力验证通过。下方未回写的详细计划按原始规划阅读，最新实际结果以应用验证报告为准。

| 优先级 | 含义 |
| --- | --- |
| P0 | 影响核心体验、技术路线或重要状态恢复，应先取得证据再承诺能力和扩大投入 |
| P1 | 在首个可用版本的小范围验证前完成的交互、数据、资源与兼容性检查 |
| P2 | 小范围真实使用和进一步市场研究，不以内部功能检查代替 |

每项验证应记录：结论日期、设备与系统版本、应用或原型版本、前置设置、操作步骤、实际结果、可复现证据、受限边界、涉及的需求变更。结论可为通过、部分通过、未通过或证据不足。

支持系统、设备矩阵、性能阈值及部分交互参数尚未锁定。应先形成建议并确认，不把个人测试设备范围或任意测试数值直接当作产品承诺。

## 3. 核心系统能力

### V01 全面通知屏蔽的真实可达范围

- **问题**：在不依赖快捷指令、不通过系统总静音处理的条件下，能够控制哪些通知弹窗和提示音？
- **检查**：普通应用通知、时效性通知、来电或通信提醒、系统通知、关键警报、应用内自绘通知；视觉和声音分别测试。允许应用与未允许应用均需覆盖。
- **边界**：区分通知弹窗、普通内容弹窗、权限或安全确认。明确哪些可控制、哪些由系统保留、哪些无法可靠检测；不靠读取工作内容扩大能力。
- **证据**：逐渠道列出配置、触发方法、开启前后效果、恢复结果及已知例外。不能仅凭权限状态或接口返回值判定全部生效。
- **决策**：2026-10-23 用户明确接受系统 Focus 可控制的标准通知；关键警报、部分系统／来电及自绘提醒作为明确例外。标准通知仍须证明实际弹窗、声音与恢复，不能只验证接口返回值。历史“全部通知”目标已由产品需求 v1.1 的 R06 覆盖。

### V02 无快捷指令的本地联动与一次性配置

- **问题**：能否在一次性配置之后，由本产品日常开始、暂停、恢复和退出自动联动通知保护？
- **检查**：只评估满足无快捷指令约束的路径；列清必要系统权限、原生适配和首次配置步骤，验证重新启动后是否保持。
- **证据**：普通用户可复现的首次配置与后续日常操作；列明是否需要额外安装、命令行操作或重新授权。
- **决策**：不把 Session 或 HazeOver 的快捷指令方案直接当作可采用路径。满足不了约束时提出证据与取舍，不自行引入依赖。

### V03 应用收起、范围外访问与后台任务保留

- **问题**：能否可靠收起未选择应用，在范围外访问时提供三个选择，同时保留原生工作能力？
- **检查**：浏览器、独立 AI 应用、文档编辑器、聊天应用；窗口切换、从 Dock 打开、键盘切换、重新启动应用、前台无窗口、文件选择器、拖拽及输入法。
- **证据**：AI 生成、下载或其他后台任务继续运行；“返回”“加入本次”“退出专注”不丢失用户输入，不反复抢焦点；本次临时加入不会意外改写已保存组合。
- **决策**：隐藏或收起不等于禁止启动，不得凭接口存在就承诺完整限制。不可可靠覆盖的入口需明确说明。

### V04 Go＋MyGo 的 macOS 系统适配可行性

- **问题**：主技术栈能否承载窗口、系统事件、媒体、轻量入口及必要的 macOS 专用能力？
- **检查**：原生 UI 与系统 WebView 两种界面方式的适配成本，系统事件接入、窗口行为、媒体与打包。具体选择依据验证结果，当前没有替用户锁定其中一种。
- **证据**：正式打包形态下的能力结果与依赖说明，区分开发环境可用和用户安装后可用。
- **决策**：Go＋MyGo 为已确认基线，允许系统专用适配。若出现根本冲突，先报告事实与方案，不静默更换框架。
- **工程条件复核（2026-10-22）**：本机 Go 已为 1.27.3 darwin/arm64，满足 MyGo 的 1.27.1 声明；Go 二进制、默认目标与本机 uname 均为 arm64，探针产物与运行仍待验证。用户提供的本地 MyGo 源码、文档、菜单栏／UI 示例和测试已只读核对，快照及复用边界见 [技术准备核查](技术准备核查.md)；不因此将 V04 标为通过。

### V05 暂停、退出、异常时的清理和恢复

- **问题**：环境能够建立，也能可靠撤销，并恢复本产品实际改变的状态吗？
- **检查**：进入前已开启系统专注模式、已有隐藏应用或自定义壁纸；用户中途主动修改系统状态；暂停、恢复、退出专注、正常退出程序、强退、崩溃、重启。
- **证据**：前后状态对照；不误显示原本隐藏的应用，不错误关闭用户原有系统模式，不留下遮罩、限制或持续播放的声音。
- **决策**：区分本产品拥有的改动与用户后续改动，恢复策略应尊重用户操作。无法完全恢复的情形需给出可操作的恢复方法并确认边界。

### V08 App Store 沙盒与直接分发的能力边界

- **问题**：哪些核心能力可在上架约束下提供，哪些可能只适用于直接分发？
- **检查**：通知控制、应用管理、跨应用操作、后台与原生适配的沙盒和权限要求；分别评估两种分发形态。
- **证据**：官方要求、实际能力验证和受限点。文档查阅、成功编译、签名或公证均不等于 App Store 审核通过。
- **决策**：已允许签名、公证安装包先行。如上架需减少能力，应形成版本范围提案，不默认两个渠道完全一致。

## 4. 会话与保护状态

### V06 时长输入、计时边界、到点与暂停计算

- **检查**：15、30、60 分钟及自定义；提前退出；到点一次提醒；自动转超时；手动暂停与恢复；锁屏、合盖、睡眠；界面关闭或后台运行；修改系统时间和跨日期。
- **证据**：实际累计时间符合会话状态，不重复提醒，不计入暂停和睡眠时间；超时阶段暂停后恢复到超时阶段。
- **已确认设计细节**：以上交互边界已在最新版 v0.2 设计中确认，技术验证沿用 docs/产品交互设计.md，不重新询问；实际计时、系统事件与恢复机制仍须取证，设计确认不等于验证通过。
- **约束**：不引入键鼠闲置自动暂停，不把记录解释为检测到的注意力水平。
- **可复用入口与缺口**：本地 MyGo 已有 Power.OnSuspend／OnResume／OnLockScreen；睡眠与唤醒通过 NSWorkspace 通知，锁屏通过 com.apple.screenIsLocked 等分布式通知字符串。需核实锁屏路径稳定性，并实际验证自动暂停及手动恢复；fake 单测和现有 e2e TestPower 不能证明这些产品流程。

### V07 保护状态验证与部分保护选择

- **检查**：拒绝权限、权限被撤销、通知静音失败、部分应用不能收起、无法检测某项保护、恢复失败。
- **证据**：界面能区别未配置、未验证、受限与已验证状态；只在用户明确选择后以部分保护继续。
- **体验**：默认引导解决问题，用户也能取消；进入后状态可查看，但不周期性弹窗催促。未知能力不能显示为“全部已保护”。

## 5. 工作环境、资源与质量

### V09 多显示器、多桌面和系统窗口行为

- **检查**：单屏、外接屏、不同缩放、插拔显示器、主屏变化、多个桌面、全屏应用及窗口管理功能；必要系统对话框和输入法。
- **证据**：跨屏应用规则一致、目标和计时唯一、窗口布局保留、同主题背景不挡住允许应用；不误要求全景拼接。
- **决策**：将支持范围写入结论；未测试的系统组合不标为兼容。

### V10 临时背景、原生窗口和视觉层级

- **检查**：多个允许应用并排、窗口重叠、关闭最后一个窗口、切换前台、显示桌面、深浅色环境、背景撤去。
- **证据**：相关应用均清晰；背景低干扰；不强制放大或重排窗口；没有遮罩残留、闪烁或焦点抢夺。
- **边界**：临时背景的具体呈现方法需验证；Portal 的恢复问题仅是风险线索，不证明本产品必然遇到同类问题。

### V11 四主题入场短片与场景衔接

- **检查**：森林、沙滩、雪地、草原完整性；角色、美术与声音一致；约 5–10 秒的入场体验；跳过、重复进入、媒体加载失败；过渡到安静工作背景。
- **证据**：用户知道何时开始工作，跳过始终可用，短片不阻塞退出；不需要角色操控或持续动态画面。
- **待定细节**：具体美术、分镜、编码、分辨率和过渡参数，先形成设计证据再锁定。

### V12 音乐、人声、提醒与通知静音共存

- **检查**：人声默认关闭、进入时可选且可跳过；音乐独立开关与音量；暂停停声；恢复与退出；耳机切换；到点一次轻提示与可关闭提示音。
- **证据**：通知声音被控制时音乐仍可用；到点反馈不依赖被屏蔽的外部通知渠道；工作中不突然插入人声或反复提醒；切换无明显爆音或循环接缝。
- **边界**：通知音与用户主动播放的内容分开测试，不采用系统总静音伪装成全面通知屏蔽。

### V13 离线资源、素材授权与包体取舍

- **检查**：断网首次启动、四主题本地短片与基础声音、资源缺失；图片、角色、短片、音乐、音效、人声与字体的可用授权。
- **证据**：核心流程不依赖登录、远程接口或首次联网下载；有可追溯的素材来源与使用权，竞品研究截图不混入发布资源。
- **待定细节**：基础资源的质量、编码与安装包体积取舍；新增联网资源机制不是默认获准的需求。

### V14 支持设备、系统版本与性能

- **检查**：提出最低 macOS 版本、Apple Silicon 与 Intel 支持范围，再按确认的设备矩阵检查启动、内存、CPU/GPU、播放、后台、暂停及多屏资源使用。
- **证据**：可见与不可见、动态与静态、专注与暂停状态分别测量；不可见动态内容停止无效渲染，不明显挤占办公应用资源。
- **待定细节**：具体性能阈值与包体目标尚未确认。记录测试条件与数据，再给出建议，不用厂商营销数值替代测量。

### V15 静默记录、历史删除与本地数据边界

- **检查**：开始、暂停、超时、提前退出、异常中断、重启、跨日和历史删除；偏好与应用组合保存；实际网络请求和权限。
- **证据**：记录为必要事实，不自动补算未知时间，不将会话结束标为任务完成；无复盘弹窗；用户主动可查看、可删除；不读取或上传工作内容。
- **待定细节**：异常中断后的可信时长与会话恢复呈现，应先形成规则提案，避免把应用未运行的间隔补算为有效时长。

### V16 安装、签名、公证与外部依赖

- **检查**：在目标环境安装、启动与卸载；检查签名、公证、首次配置、依赖和资源路径。
- **证据**：用户不需要另装 Go、开发工具、第三方插件、脚本工具或快捷指令；不把开发机环境当作用户的必备运行条件。
- **边界**：签名、公证与发布需要实际账号和操作条件，本轮不执行，不宣称已经完成。

### V17 轻量开始、会话控制与提示理解

- **检查**：日常只需明确或复用目标、选择时长、开始；应用、场景和声音可展开修改；暂停、恢复、退出含义清楚；目标、时长和保护状态容易找到。
- **证据**：用户能够完成主要流程，正常使用键盘，不因入口隐藏而难以退出；范围外应用提示支持有意调整，也不会持续骚扰。
- **边界**：验证准备成本、文案和操作可达性；本轮没有承诺全局快捷键、新面板系统或完整待办管理。

## 6. 竞品与真实用户验证

### V18 三款竞品的实机交互对照

- **检查**：记录 HazeOver、Session、Portal 的实际版本与系统条件，体验相关窗口、配置、开始、工作、声音、到点、暂停和退出流程。
- **证据**：按步骤记录观察，区别官方声明、实际观察与本项目推导；更新竞品文档中仅有文字或静态截图的部分。
- **约束**：仅为实现、体验与交互参考，不增加休息、网站屏蔽、云同步、强制复盘或快捷指令依赖，不将竞品素材直接用于产品。

### V19 真实需求、任务偏离与持续使用价值

- **对象**：用户本人及少量相似 AI 桌面办公者。实际人数、试用周期和邀请安排尚未确定或执行。
- **方法**：收集最近真实偏离案例，并在有代表性的工作任务中比较原工作方式与本产品体验。结合访谈、用户自述和经同意的研究观察，关注偏离、回到任务、准备负担、恢复信任和持续使用意愿。
- **证据**：既记录有效案例，也记录无帮助、被提示打断、绕过限制、关闭场景或放弃使用的情况；区分场景新鲜感与持续价值。
- **测量边界**：应用切换不等于任务偏离；浏览器内偏离不在产品识别范围。累计时长、打开范围外应用次数或画面喜好不能独立证明专注改善。研究访谈不能变成产品每次结束后的强制复盘。
- **决策**：先验证当下保护价值，不据此直接宣称长期注意力训练效果，也不提前锁定收费模式或扩大到学习人群。

## 7. 建议的验证顺序

1. **确认能力边界**：V01–V05、V08，先明确通知、应用管理、技术栈、恢复和分发约束。
2. **验证闭环体验**：V06、V07、V09–V12、V15、V17，覆盖开始、工作、到点、暂停与退出。
3. **确认交付质量**：V13、V14、V16，补足资源授权、离线、设备和安装证据。
4. **持续研究与试用**：V18、V19，完善竞品实机依据和真实用户价值证据；需求访谈可以先行，不必等待完整版本。

该顺序保留为最初规划。用户后续已明确授权开发和自主验收，当前范围见应用 spec D1–D9。最新证据见 [非 Focus 整体验收](非Focus整体验收.md)，不再沿用“仅文档”的历史限制。

## 8. 场景覆盖速查

| 场景 | 期望结果 | 验证编号 |
| --- | --- | --- |
| 原本已经开启系统专注模式后进入，再退出 | 妥当恢复原状态，不简单关闭系统专注模式 | V02、V05 |
| 通知控制失败或无法验证 | 不显示全部生效，用户可配置、明确选择部分保护继续或取消 | V01、V07 |
| AI 在后台生成时进入专注 | 任务继续，不被应用收起操作终止 | V03 |
| 两个允许应用并排、分布两屏 | 正常清晰、布局保留、计时一致 | V09、V10 |
| 拖拽文件、使用输入法或系统文件选择器 | 正常操作，不被误拦截 | V03、V09、V17 |
| 未允许应用被用户主动打开 | 提供返回、加入本次、退出专注的明确选择 | V03、V17 |
| 倒计时归零，用户继续工作 | 一次轻提示后继续累计，保护不撤销 | V06、V12 |
| 超时后暂停，再恢复 | 暂停不计时，恢复继续超时阶段 | V06 |
| 合盖后第二天打开 | 仍为暂停，不补算睡眠时间，等待主动恢复 | V05、V06 |
| 阅读或等待 AI，长时间不操作键鼠 | 不因静止自动暂停或判断分心 | V06、V19 |
| 强退或崩溃后重开 | 有恢复路径，不残留限制，不补算未知时间或标记目标完成 | V05、V15 |
| 断网启动 | 本地核心流程与基础场景、声音可用 | V13、V16 |
| 提前退出与查看历史 | 静默保存事实，无复盘；历史可主动查看和删除 | V15、V17 |
