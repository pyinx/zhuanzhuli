# 通知保护：已确认边界、联动实现与验证缺口

更新：2026-10-24。用户已明确接受 R06 改为系统专注模式可控制的标准通知，并接受关键警报、部分系统／来电及自绘提醒例外。该答复批准范围调整及继续联动实现，不代表授予系统权限或能力已验收。

## 结论

在“不引入快捷指令、不使用系统总静音、不写私有配置”的约束下，全面覆盖全部渠道的方案没有得到验证。当前已加入公共 Accessibility／控制中心的实验性联动适配和恢复策略，但真实系统切换、弹窗和声音仍未验收；开始和恢复保留明确部分保护选择。

初轮正式应用只读审计显示 accessibilityTrusted=false，拒绝路径提示明确。用户后续授权并完成系统认证后，最终记录 105 为 AX=true、模式列表可读、面板自动关闭失败、pending=false、未切换 Focus；通知专项仍退出 3。权限及读取成功不等于屏蔽生效。

## 当前实现及使用边界

设置中可保存专用 Focus 名称并明确开启实验性自动联动，默认关闭。用户先在系统设置中建立同名模式，配置标准通知不放行，并自行授予本应用辅助功能权限。应用不创建／删除模式、不更改联系人或允许列表，也不通过本应用触发系统安全授权弹窗。上述配置尚未在本机完成，不把说明当作配置已完成。

开始和恢复后，串行环境 worker 尝试打开控制中心，使用实际暴露的辅助功能动作，要求完整且明确的模式开关列表和唯一名称；未知结构、占用中的面板、权限不足均返回受限，不回退坐标、全局按键、快捷指令或私有 API。用户 D12 单独批准的一次定向 Escape 关闭路径已先在只读探针中实际通过，再接入生产；发送前复核同一控制中心实例、唯一自有窗口及键盘前台，发送后读取窗口消失。模式切换和恢复仍不能宣称 macOS 15 已完整兼容。

已有其他 Focus 时保留它并报告受限；已有同名模式时只借用，不在结束时关闭。仅在原来全部关闭时记录 pending，发送开启请求后观察到目标状态才写 applied；暂停、结束、取消入场和正常退出使用同一清理路径，恢复前重新核对。状态未知或重启后不自动关闭系统模式，设置提供“核对通知收尾…”入口。用户已批准 D13：用户暂停、结束、退出时提供保留当前模式／关闭此模式／稍后核对；自动暂停和异常重开不主动打开系统面板或核对窗。

租约策略测试使用明确的内存驱动，只证明决策与失败策略，不证明控制中心适配或通知效果。连续运行期间外部关闭再开启同名模式（ABA）无法靠当前名称／布尔值区分。本轮回归先复现误关闭，随后修复：同名模式仍开启时也不自动关闭，返回未知归属、保留当前状态与待核对记录，需显式核对；已观察到外部关闭或其他模式时不再发送开关。**此前严格自动恢复要求现已由用户明确改为 D13 确认式收尾**。生产代码已接入：保留只释放本地记录；明确关闭重新读取指定模式，确认实际关闭与面板清理后释放记录；失败保留、可重试；稍后核对保留记录并阻止新开始／恢复。这不证明真实系统切换成功。新窗口因本轮桌面锁定尚缺实际点击与截图，通知抑制效果也未验证。完整进展见 [开发完成度](功能开发完成度.md)。

系统 Focus 可以减少普通通知，但关键警报可能越过 Focus。允许联系人、来电、时效性通知及智能突破等配置也影响实际覆盖。以本应用作为 Focus 自动化触发条件不能覆盖跨应用工作，因为关闭或切换该应用会关闭对应自动化。[Apple：macOS 15 设置专注模式](https://support.apple.com/en-gb/guide/mac-help/mchl613dc43f/15.0/mac/15.0)、[通知设置与关键警报](https://support.apple.com/en-gb/guide/mac-help/mh40583/15.0/mac/15.0)。

## 路径比较

| 路径 | 已确认的能力 | 尚缺什么 |
|---|---|---|
| UserNotifications | 当前应用自己的授权、待发和已发通知 | 不提供任意应用的全局屏蔽开关；清理已发通知不是阻止未来通知 |
| Focus Status／Focus Filter | 在各自接入前提下读取状态、让本应用响应系统 Focus | isFocused 是可空且与调用应用相关的通知状态，不是模式名或总开关；Filter 是系统到应用的配置通道，不是全局切换接口 |
| 用户一次性配置专用 Focus | 可减少常规通知；不依赖快捷指令 | 生产流程已有实验性联动接入，实际系统切换和通知效果未验收；不覆盖已确认例外 |
| 辅助功能操作控制中心 | 当前 AX 已授权；实际读取模式和受限关闭通过，未使用私有开关 | 真实切换与通知效果未验；存在界面兼容、状态持续观察和恢复归属风险 |
| 通知配置描述文件 | macOS 支持按 bundle ID 配置，含声音与关键警报选项 | 没有已确认的全局通配；是持久策略，不是会话开关；安装／撤销和精确恢复仍不满足消费级一键流程 |

API 依据：[UNUserNotificationCenter](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter)、[INFocusStatusCenter](https://developer.apple.com/documentation/intents/infocusstatuscenter)、[Focus Filters](https://developer.apple.com/documentation/appintents/focus/)。

描述文件在 macOS 可以手动安装，**不能简单说必须有 MDM**。Apple 的载荷定义要求逐项 BundleIdentifier；手动安装需在系统设置中审查，某些情况下需密码。当前系统的 profiles 工具不提供安装描述文件能力，不能将单边移除命令当作完整开关方案。[Apple：Notifications 载荷](https://developer.apple.com/documentation/devicemanagement/notifications)、[单应用通知项](https://developer.apple.com/documentation/devicemanagement/notifications/notificationsettingsitem)、[macOS 15 安装描述文件](https://support.apple.com/en-gb/guide/mac-help/mh35561/15.0/mac/15.0)。本机另核对 profiles(1) 和 Xcode 26.2 SDK 的 Intents／UserNotifications 头文件。

## 实测与纠正

只读审计 run-20261023T094922-5324cd54 分别在 Host、Fixture A、Fixture B 的真实进程中读取设置：三者通知授权和 Focus 授权均为 not-determined；Focus 状态为未知，辅助功能信任为 false。没有请求新权限、发送通知或修改 Focus。这不能证明屏蔽生效。

此前用户看到“MyGo：the user does not allow notifications”。这条原始错误有效，但**不能据此断言用户点击了拒绝**。MyGo v0.6.2 的通知实现没有保留 requestAuthorization 回调的原始原因，而将后续 UNErrorDomain code 1 映射为该错误。历史授权当时未读取；当前 not-determined 也不能反推历史状态。测试包为链接器临时 ad-hoc 签名，尚无稳定签名后的正向通知基线，签名是否导致该次错误没有得到证明。原始日志保持不改写。

## 明确授权后的实机进展

用户已明确允许专注力辅助功能和自有夹具通知。原应用包严格签名检查失败；修正为绑定 bundle ID、Info.plist 和资源的本地 ad-hoc 签名后，重新添加应用条目，实际应用进程确认 AX=true。此签名不是开发者身份签名或公证；重新构建会改变身份，不能用设置中旧开关代替新进程权限检查。审计改用原路径应用和独立空数据，避免复制包误读权限。

已授权进程执行生产适配器，先后暴露记忆的 Focus 详情页、入口角色、异步转换与关闭问题。最终记录 105 已实际读取勿扰模式 off，但面板自动关闭仍失败；代理最后用 CUA Esc 清理，不计作应用自身通过。原始各轮记录保留，未切换任何 Focus。系统设置当时只有勿扰模式、跨设备共享为 on，没有修改该共享设置。

FixtureA 的 run-20261023T160837-310a03d4 原始授权回调 granted=true、请求 requested=true；后续只读进程审计 authorization=authorized、alertSetting=enabled、soundSetting=enabled。横幅和实际声音仍无正向观察证据。测试通知通过夹具自身清理，进程正常退出。历史 MyGo 发送错误的原因仍不反推。

本轮更新权限条目时出现系统 Touch ID／密码认证，已请求用户在系统窗口完成，不读取或填写凭据。随后系统条目移除成功，重新添加当前构建并由实际进程再次确认 AX=true。通知效果、同模式 ABA 和锁屏恢复仍是整体验收阻断。

## 系统能力复用调研

2026-10-24 复核：[INFocusStatus](https://developer.apple.com/documentation/intents/infocusstatus) 仍表达通信通知偏好；[官方 Focus Filter 样例](https://developer.apple.com/documentation/appintents/defining-your-app-s-focus-filter) 由系统在模式启停时调用应用，不能据此反向控制系统。此次官方 Markdown 已成功取得并归档 `.validation/focus-api-20261024/`，不沿用历史抓取 404 推断接口能力。本机 SDK 的 INFocusStatusCenter 提供只读状态与授权入口；App Intents 虽含 preciseTimestamp，没有本次需求所需的系统状态所有权版本或条件切换事务。轮询与本地时间戳不能证明漏读期间没有同名 off→on。因此通知自动恢复仍未实现；[具体范围选项](../.harness/changes/2026-10-23-focus-application/notification-recovery-decision.md) 待产品决定，本轮保持系统原设置。

最新受限关闭开发：D12 批准仅针对本次打开且同进程、同窗口、仍键盘前台的面板发送一次无修饰 Escape，公开接口为 CGEventPostToPid；不发送全局事件、不切换 Focus。刷新同路径已有授权并修正无 launchDate 的进程身份适配后，190 只读关闭通过；随后接入正式适配器，192 再次通过，193 生产只读诊断无关闭错误。三次均实际读取勿扰模式 off、未切换 Focus、pending=false；真实切换、通知效果和连续恢复归属仍未解决。新探针缺权限分支不调用 Acquire，退出也不能继承旧租约。详见 [开发完成度](功能开发完成度.md)。
