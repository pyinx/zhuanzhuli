## 受限关闭探针开发

复用 FocusDriver 的空闲窗口检查、精确窗口身份和现有原生接缝，新增单次关闭器及 `--notification-check --panel-close-probe` 隔离入口。只使用公开的 `CGEventPostToPid` 定向接口，要求既有 AX 权限、相同进程实例、唯一自有窗口、AX 键盘前台应用和窗口均匹配；一个无修饰 Escape 按下／抬起，不做全局发送或重试。SDK 头文件核对了 C ABI 和 Escape 键码。

探针在任何应用数据初始化前拒绝非空目录，不能继承通知租约或环境恢复记录；两个只读通知诊断的未授权分支也不再进入 Acquire，避免权限在两次检查间改变后误入切换路径。只读回调只调用 Modes，不调用 Set。关闭后仍由 WithPanel 实际读取窗口消失；事件发出不算关闭成功。190 实际通过后才接入正式适配器，每次 WithPanel 在打开前创建独立关闭器，用后释放；Acquire 的两次往返不会共用已尝试过的关闭器。

新增边界策略检查与真实 CF／CG ABI 检查，这些测试本身不发送按键；原清理路径把窗口缺失、AX 错误或类型异常当作无错误返回，回归 175 先失败，现改为明确拒绝。最初因 AX=false 与锁屏受阻；用户完成系统认证后，原条目开关刷新仍不能绑定新构建，重新添加同路径应用后真实进程确认 AX=true。没有授予其他应用权限。

进程身份检查还暴露控制中心没有 launchDate（187；只读元数据核对为进程存在、未终止、日期缺失）。本机 NSRunningApplication.h 明确该日期不覆盖未经 LaunchServices 启动的应用，并要求用 isEqual: 比较进程；因此为本次短暂关闭保留 NSRunningApplication 实例，复核 isEqual:、未终止、PID、唯一 bundle ID 与路径。持久应用恢复日志仍使用原 Describe，不放宽其身份要求。原生检查 189 确认无需 AX 权限即可捕获该进程身份；后续 190／192 实际关闭通过。只读和策略证据均不能代替模式切换、通知效果或连续恢复归属，后三项仍未完成。
