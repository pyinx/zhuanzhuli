## 4. 系统能力的证据边界

Apple 的 Focus 配置涉及允许的人与应用、时效性通知等规则；通知设置还可能允许关键警报在 Focus 开启时显示。因此“打开 Focus”本身不能证明已覆盖全部通知类型。[Apple：Focus 配置](https://support.apple.com/en-gb/guide/mac-help/mchl613dc43f/26/mac/26)、[通知设置](https://support.apple.com/en-gb/guide/mac-help/-mh40583/mac)

公开资料中的 INFocusStatus 用于表达用户接收通知的偏好，Focus filter 用于让本应用适应系统 Focus 的变化。已读资料没有证明本产品可以直接切换全局 Focus 或全面屏蔽其他应用的通知；这里的结论是“尚未证实”，不能据此断言所有路径均不存在。[Apple：INFocusStatus](https://developer.apple.com/documentation/intents/infocusstatus)、[Focus filters](https://developer.apple.com/documentation/appintents/focus/)

应用隐藏、启动拦截、前台访问检测和窗口恢复是不同能力。已有 Apple 接口入口可以作为研究起点，仍需在限定的测试对象上证明成功、拒绝、重复调用和清理结果。[Apple：NSRunningApplication.hide](https://developer.apple.com/documentation/appkit/nsrunningapplication/hide%28%29)

完整通知目标、无快捷指令、不用总静音替代、后台任务保留与尊重原有环境均保持原需求。不达目标时应报告受限矩阵和决策选项，不静默缩小产品范围。
