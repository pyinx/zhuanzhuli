# 基于首轮技术证据的实现设计

日期：2026-10-23。状态：实现设计建议，存在明确阻断；不授权完整应用开发。产品需求和 v0.2 苹果风格设计保持原基线，技术事实见 [技术验证结果](技术验证结果.md)。

## 1. 目前可以决定什么

Go＋MyGo 的基础构建与原生窗口承载在当前 macOS／arm64 上可行。跨应用收起与后台持续已在两个自有夹具取得实证，恢复归属与延迟观察需要由本产品维护，不能交给 hide／unhide 的布尔返回值。

全面通知保护仍未证实。因此下面是可继续验证的结构，不是“核心能力都可行”的最终工程承诺；正式应用是否推进，需要先处理通知目标与剩余重要验证。

## 2. 两种正式实现候选

| 方案 | 证据与收益 | 成本／未决事项 |
| --- | --- | --- |
| A：Go 会话核心＋MyGo ui＋系统窗口／菜单＋macOS 适配 | 纯 Go、窗口与面板已实际建立，辅助功能树有语义控件；更容易保持开发与用户依赖简单 | 自绘控件不等于 AppKit 控件；真实中文组合输入、VoiceOver、材质、焦点与减少动态仍须补证 |
| B：同一 Go 核心＋系统 WKWebView＋系统窗口／菜单 | 新建测试表单已实际运行、可用中文字符串、共享同一会话；DOM 语义可作为另一条实现路径 | 需要维护 IPC、导航／来源边界和与 macOS 一致的控件交互；测试表单的网页样式不是正式苹果风格设计 |

建议先沿 A 补齐原生体验证据，并保留 B 作对照。尚不把建议写成用户已确认的正式 UI 技术选型；只有一个会话核心，两个视图不各自计时。继续固定 MyGo v0.6.2；有明确发布版缺陷才提出带复现证据的版本变化，不自动跟随本地 HEAD。

## 3. 所有权与边界

| 所有者 | 唯一负责的状态／不变量 | 已有验证入口 |
| --- | --- | --- |
| 会话控制器 | entry／active／overtime／paused／ended、有效时长、到点一次标记、本次允许集合、待选择状态 | internal/session；菜单与两个视图都投递命令／读快照 |
| macOS 适配 | 实例身份、请求发送、系统事件、跨事件循环后的实际状态 | internal/macos；仅当前明确夹具可写，不掌握会话策略 |
| 改动日志 | pending／applied／released／abandoned、归属、失败和恢复记录 | internal/journal；原子写与持久化失败测试 |
| 延迟观察 | 单次请求后等待条件，真实失败、未确认与超时分开 | internal/probe；未确认但稍后生效的回归测试 |
| 视图与原生选择面板 | 呈现快照和必要选择，不另计时、不自建允许集合 | cmd/host；同一控制器，首次待选择转移才呈现面板 |
| 能力事实 | 渠道、操作、结论、证据种类与引用，未知不得冒充保护生效 | matrix.json／observations.json；原始依据与实测分列 |

其他平台未来在相同系统接缝提供自己的实现；当前不建立跨平台通用桌面控制器、不承诺最低系统版本。macOS 专用行为不可为了跨平台削弱，必要适配随产品打包；开发 Go／工具链不成为用户依赖。

## 4. 会话、保护与恢复

计时只计算已进入活动阶段的有效区间，暂停不累积，唤醒不自动恢复，超时继续由用户决定。使用 Go 单调时间处理进程内时长；重启或无法确定的区间不补算。已取得自然锁屏／睡眠与解锁后保持暂停的事件证据，不能用键鼠闲置启发式替代。内部时钟观察不分配用户命令 ID，不占去重额度，避免隔夜失效。

会话状态与保护状态分开。通知权限被拒绝、其他应用无法收起、状态无法读取或恢复失败，都应显式显示未验证／受限；只有用户明确选择才以部分保护继续。到点提醒不应只依赖可能被屏蔽的系统通知，最终提醒媒体还未制作。

系统改动先记录基线和 pending，再发送一次请求，跨 run loop 观察后标 applied。暂停、结束、退出共用清理，重复请求不产生第二次副作用。只撤销已观察且仍能证明归属的改动；原本隐藏不拥有，用户中途操作放弃归属，实例变化不操作新实例。已实测 applied 条目的宿主异常重启与清理；pending 崩溃窗口和相同状态下无法区分的用户操作仍必须保持 unknown／受限，不能承诺完美恢复。

范围外应用激活后需要实际可见的必要选择面板。只更新后台表单不满足交互要求；重复事件合并，关闭不自动选择，返回／加入本次／退出走同一控制器，本次加入不改默认组合。所有共享状态变化必须刷新主窗和面板，避免按钮保持过期的禁用状态。非激活面板的“返回”先确认宿主获得前台，再交接到允许应用，并检查实际结果；不能把请求返回值当作切换成功。三个按钮已实际操作，跨 Space、Esc 和完整辅助功能仍需覆盖。

## 5. 权限与数据

优先公共系统 API 与现有 MyGo 能力，不请求不需要的权限。通知权限拒绝必须保留并引导，由用户选择是否处理；程序不替用户更改设置。截图只接受当前自有窗口与既有捕获权限，不主动申请、不录制音频或屏幕。

当前只有版本为 1 的本地实验 JSON／JSONL，无生产数据或迁移。正式偏好、历史记录与删除契约仍沿 v0.2，后续开发才确定生产存储方案；不要把实验 journal 当历史数据库。日志不保存专注目标文本、应用内容、窗口标题或剪贴板；生产阶段还需验证完整的数据保留与删除路径。

## 6. 后续开发任务与阻断条件

| 顺序 | 必须先解决 | 验证／阻断 |
| --- | --- | --- |
| 1 | 符合无快捷指令、非总静音约束的通知控制路径 | 六渠道弹窗／声音、首次配置、日常联动和恢复逐项有证据；无法满足时先提交产品范围决策，不静默降级 |
| 2 | 范围外面板与恢复完整场景 | 用户能看见并操作三种选择；真实后台任务与第三方样本、原本隐藏、竞争、中断／重启、拒绝和重复操作取证 |
| 3 | UI 承载方式定型 | 同条件中文候选、Tab／Esc、系统菜单、关闭／退出、深浅色／辅助功能／VoiceOver；不能用截图或字符串输入替代 |
| 4 | 审查技术结果与明确支持范围 | 当前设备结果不扩大到 Intel／universal／所有 macOS；完成独立审查与阶段验收 |

本轮没有开始第 5 项，也没有为了绕过能力阻断改换技术栈或改写已确认设计。
